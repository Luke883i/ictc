# ICTC 1.4 stable — holistic end-to-end audit

## Decision

The merged experience is directionally strong but not yet sufficient for a first-time enterprise user or an EU auditor. The Home explains the next task and the human/AI boundary, but authority is still inferred from hidden controls and scattered copy. A reviewer cannot immediately answer: who authenticated, which capabilities were issued, what this actor may change, which actions are forbidden, what state effect follows and which evidence is produced.

ICTC 1.4 stable therefore keeps the three-region Home and adds one compact, server-backed authority map. Detail is progressive: the primary task remains visible; access, powers, effects and evidence are available in one disclosure and open by default for the auditor.

## Simulated first experiences

### Novice

The current decision capsule answers the immediate task, but terms such as governance, candidate source, receipt and runtime still require prior knowledge. Navigation numbers add decoration without meaning. The novice needs plain labels, one task, one method and a concise explanation of the result.

### Operator

The operator can report an event and add material, but the wording must consistently preserve the distinction between raw material, a candidate or verified source, and evidence. "Add a source" before review is ontologically wrong and can create false confidence.

### Administrator

The administrator sees many powers but must infer their consequences. Enterprise UX requires every state-changing action to expose its effect, human checkpoint and receipt boundary. Deployment blockers must remain visible and must not be presented as application success.

### EU auditor

The auditor can read evidence and is prevented from writing, but a satisfactory audit also needs an explicit access narrative: active identity, access mode, allowed and forbidden capabilities, affected state and evidence trail. The hash chain and exported bundle demonstrate recorded operations and internal consistency, not legal applicability, completeness or substantive truth.

## Density findings

High cognitive density occurs in the right side of the Home decision capsule, monitoring source review, incident formulation, AI settings and the administration center. Low density occurs in the large action column, hero padding and decorative navigation numbering. The 1.4 design reallocates that space: the action column shrinks, explanatory cells tighten and the new authority map uses disclosure rather than another card.

## Minimum materialization path

1. Define the 1.4 contract, invariants, metrics and N+100 saturation.
2. Project a canonical access profile from the backend bootstrap response.
3. Render one compact authority map and simplify shell labels.
4. Compress decision, method and status geometry without reducing 44 px targets.
5. Propagate version 1.4.0 across runtime and claims.
6. Certify admin, user and auditor journeys plus contract, runtime and security gates.

## Claim boundary

This audit evaluates repository behavior and selected runtime/browser journeys. It does not certify a production deployment, legal compliance, accessibility conformance, identity-provider configuration, TLS, durable storage, backup, malware scanning or organizational operating effectiveness.
