## User requirement lattice

The nine requested quality themes are represented losslessly as six enforceable axes: single UI truth; progressive disclosure; editorial grammar; visual semantics; local specialization; falsification. Concretely P2 requires one surface identity, one primary attention count per semantic dimension, at most one first-plane primary action, closed secondary disclosures, readable material boundaries, row/list defaults for homogeneous records, distinct reference/evidence/boundary roles, compressed chrome utilities, a compact Admin configuration grammar, a librarian-style RN register grammar, and a single progressive EP trajectory.

## Material changes

- Procedure Frame separates identity, purpose, boundary and primary action; the boundary may wrap and must not be ellipsized.
- Worklist count becomes an explicit `attention` metric owner instead of part of the title.
- GRC local owners classify aggregates as `distribution` or `analysis`; RC heatmap is analytical context and MC mapping aggregate is explicitly non-conformity evidence.
- Admin process availability uses comparable `ConfigurationRow` semantics; acknowledgement remains diff-only.
- Evidenze distinguishes decision, reference, evidence, relationship, external-boundary and technical clusters; all secondary disclosures start closed and then preserve user state.
- EP keeps its material claim boundary visible and subordinates professional lenses and AI inference under one `Approfondimenti e strumenti tecnici` disclosure. Graph/raw remain progressive technical modes.
- Historical mobile CSS no longer rewrites the canonical `Evidenze ICTC` label to `Postura ICTC` through generated content.
