# A6-UX4 UI/UX mount audit

Evidence class: E2 repository/model plus exact-head browser when CI is green. This document is not human-usability evidence, accessibility certification, legal/compliance proof, deployment evidence or an enterprise-ready claim.

## Canonical end-user questions

Every operational surface must make these questions answerable without reading raw provenance or technical history: what must I do now; on what subject; why it needs attention; what useful state it is in; whether I can act or only inspect; what the control changes; what source/evidence supports it; which decision remains human; what ICTC does not know; whether a label implies certification/compliance; how to see non-actionable records; where standards/references live; how organizational use differs from applicability/mapping; whether the path reflows on mobile; whether read-only roles remain read-only.

## Negative patterns mined from the supplied screenshots

The deterministic 100k campaign covers 25 visual-semantic failure families: duplicate operational collection, duplicate toolbar, ugly reveal control, duplicate heading, material-aside width theft, context-label duplication, weak reference band, usage-badge overclaim, reference-label duplication, modal horizontal overflow, dominant arrow affordance, technical-first proof, raw-state leak, action-effect ambiguity, unbound actionable target, fail-open hidden work, independent palette owner, role write leak, mobile clipping, claim laundering, terminal-default leak, dead-end empty state, multiple primary actions, unstable record binding and worklist/native drift.

## Mount invariant

S1/A1 remains canonical for actionable membership and typed target refs. A6-UX4 may hide the separate worklist only when every actionable row resolves to a native local record. On any unresolved binding the canonical worklist remains visible. Integrated native collections default to `Azioni correnti` and expose `Tutti gli elementi` in the same local toolbar.
