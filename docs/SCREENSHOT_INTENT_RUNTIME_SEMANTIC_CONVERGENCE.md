# Screenshot Intent Runtime-Semantic Convergence

Baseline: `main@678d3e86cdce1043e7d6ff0fb8ba45cb679ade39`.

## Problem lattice

This slice treats the red screenshot annotations as product requirements rather than cosmetic tickets. The converged root causes are:

1. procedure support information was physically inside the canonical `header` even when copy/tests called it “below the header”;
2. Home viewport-fit was source-level arithmetic rather than an end-to-end geometry invariant;
3. AI state was projected correctly but the design-system could recompute a presentation tone from icon-only text, creating a false-green path;
4. procedure availability was writable but landing readback was insufficiently fail-closed and weakly falsified;
5. provider configuration lived in a separate modal despite Admin already being the control-plane owner;
6. Standard Browser gave too much visual authority to the index while closed-source nodes only had generic descriptions;
7. RN scheduled mining existed as a secondary registry but did not guarantee visible materialization when jobs became real.

## Local DoD

- `.procedure-support-rail` is a direct sibling immediately after `.procedure-frame`; context and standards are never children of the header.
- AI `data-ai-state` has an explicit presentation mapping: ready→positive, key-missing→attention, unconfigured→neutral. Tooltip and route language agree.
- Procedure policy save performs bootstrap readback; the Processi landing is rendered from the projected enabled set and disabled procedures disappear.
- Procedure switches remain native controls with readable state labels.
- The unique `#settingsForm` is adopted by Admin > AI. No second provider form or write API is introduced.
- RN job registry stamps count/state and opens when the first real job materializes.
- Standard Browser index is bounded; the detail pane remains primary reading space. Licensed/closed nodes receive original ICTC structural descriptions, keywords and compressed outlines without reproducing proprietary wording.
- Desktop Home budget includes header, footer and main padding without hiding overflow to manufacture a pass.

## Intermediate DoD

- Existing authority owners remain authoritative; no new global resolver or business-write owner is introduced.
- Historical browser/source oracles are updated from “support rail exists” to parentage/order/runtime geometry.
- Procedure disablement is falsified across admin write → bootstrap projection → landing readback → route/write blocking.
- AI false-green is falsified across runtime state → semantic tone → tooltip → computed surface contract.
- Standard content origin remains explicit: official exact text, authorized pack, ICTC neutral index and reference-only are distinct.

## Global DoD

A blocking deterministic rail executes 1,000,000 semantic mutation trials over 20 independent families covering parentage, viewport truth, AI state/tone/copy, feature policy, Admin/AI ownership, Standard Browser geometry/content boundaries, RN mining materialization and single-authority constraints. Browser/runtime gates remain independent evidence.

## Source debt / claim boundary

The repository does **not** claim that exact complete public-law text is bundled by this slice. Exact public text is shown only after a complete, versioned, official-source-confirmed pack passes `standard-public-source-pack.mjs` completeness and provenance checks. This PR does not copy, reconstruct or fabricate missing official text.

For licensed/closed standards, the shipped material is an original ICTC structural description and thematic index only. It is not normative wording, a substitute for a licensed standard, legal interpretation, applicability, certification or control-effectiveness evidence.

## Evidence classes

- source/model mutation evidence: repository-bounded;
- browser geometry/readback: server-backed automated evidence;
- official-source completeness: debt-blocked until an authoritative pack is supplied;
- human usability, assistive-technology assessment and deployment assurance: outside this PR.
