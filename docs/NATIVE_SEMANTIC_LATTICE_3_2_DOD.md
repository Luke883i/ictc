# Native Semantic Lattice 3.2 — DoD

## Stato target

**ICTC Enterprise Compliance Workspace 3.2 — Native Semantic Lattice**.

La 3.2 conserva gli invarianti acquisiti con Semantic Composition 3.1 ma sposta la gerarchia informativa verso owner locali. `active-experience.js` resta l'unico composition root: installa gli owner locali 3.2 e successivamente il kernel globale `semantic-composition-runtime.js`, che è annotation-only. Nessuna nuova business write authority e nessun nuovo participant C0.1.

## DoD globale

1. Esistono esattamente sette processi business; EP-01 resta cross-cutting e non diventa un ottavo processo.
2. `semantic-composition-runtime.js` contiene zero adapter locali, zero business-copy rewrite, zero local DOM reorder e zero bootstrap di owner locali.
3. Il composition root installa Foundation 3.0 -> local native owners 3.2 -> global semantic annotation; C0.1 conserva `harmonization -> presentation -> integrity -> journey -> annotation`.
4. Catalogo e workspace non condividono lo stesso copy: `catalogueSummary != workspacePurpose` per 7/7 procedure.
5. Il catalogo Processi usa capability card a matrice 3 -> 2 -> 1; le collezioni di record omogenei restano list/row.
6. Home presenta identità e funzione aziendale di ICTC prima della bounded attention queue; nessuna dashboard numerica autonoma.
7. Evidenze ICTC apre Decisioni e organizza progressivamente Evidenze e basi, Verifiche esterne, Integrità/Export e metodo di lettura.
8. EP-01 rende ricerca/relazioni primarie; compression, summary, boundary e dettagli tecnici sono progressivi.
9. Admin esplicita che la disponibilità procedure controlla nuovo lavoro/routing/automazioni e non applicabilità legale; conferma solo su diff.
10. Header/footer usano chrome scuro a gradiente e controlli/contrasti chiari senza usare colore come giudizio di conformità.
11. 320/390 px non introducono overflow orizzontale nelle superfici coperte.
12. GRC riconverge dopo il render canonico mediante un segnale di context commit; il local owner non deferisce il proprio pass di composizione.
13. La slice è verificata da gate statici/UI, 10M model-vocabulary trials, stress code-bound del contratto C0.1 e browser journey; exact-head CI resta acceptance separata.

- Foundation 3.0 -> local native owners 3.2 -> global semantic annotation -> C0.1 final convergence.

## Limiti

Le campagne deterministiche sono bounded repository/model evidence. Il conteggio 10M misura esplorazione del vocabolario di failure dichiarato, non dieci milioni di mutazioni del codice, browser session o prove indipendenti. Lo stress C0.1 esercita codice del contratto costituzionale, non un milione di replay browser. Nessuna campagna costituisce parere legale, studio con utenti, certificazione di accessibilità, security assessment del deployment o assurance indipendente.

La branch protection server-side, la review indipendente e gli altri gate di deployment non possono essere auto-chiusi da test repository-side. Il merge richiede osservazione dell'exact PR HEAD e dei check GitHub applicabili; un repository senza branch protection resta esplicitamente privo di enforcement server-side.
